# 📜 CODEFORGE'26 — API CONTRACT & SPECIFICATION

**Project**: Student & Staff Wellbeing Platform  
**Backend Base URL**: `https://codeforge-zdxk.onrender.com` / Local: `http://localhost:8000`  
**Frontend Base URL**: `https://codeforge-0j8e.onrender.com` / Local: `http://localhost:5173`  
**Authentication**: Bearer JWT (`Authorization: Bearer <token>`)

---

## 🔒 Privacy Boundary & RBAC Principles

1. **Student Role (`student`)**:
   - Accesses only their own check-ins, personal metrics, and private notes.
   - Enforces unique constraint: **1 check-in per student per calendar date**.
2. **Staff Role (`staff`)**:
   - Accesses aggregate support signals generated by the Pattern Engine.
   - **STRICT PRIVACY SHIELD**: Staff **NEVER** receive or see `private_note` or personal reflection entries.

### 2. Authentication & Users
- `POST /api/v1/auth/register`
  - Request:
    ```json
    {
      "name": "Atharva Dev",
      "email": "atharva@campus.edu",
      "password": "securepassword123",
      "role": "student"
    }
    ```
  - Response (`201 Created`):
    ```json
    {
      "access_token": "eyJhbGciOi...",
      "token_type": "bearer",
      "user": {
        "id": "usr-12345678",
        "name": "Atharva Dev",
        "email": "atharva@campus.edu",
        "role": "student",
        "picture": null,
        "created_at": "2026-09-08T00:00:00Z"
    ```

- `POST /api/v1/auth/login`
  - Request:
    ```json
    {
    ```

  - Headers: `Authorization: Bearer <token>`
  - Response (`200 OK`): Current User profile.

### 3. Daily Check-in (Student Only)

- `POST /api/v1/checkins`
  - Headers: `Authorization: Bearer <student_token>`
  - Request:
    ```json
    {
      "date": "2026-09-08",
      "mood": "neutral",
      "stress_level": 4,
      "sleep_quality": 2,
      "nutrition": 3,
      "physical_activity": 2,
      "academic_pressure": 4,
      "social_interaction": 3,
      "private_note": "Exam tomorrow morning."
    }
    ```
  - Enum Definitions:
    - `mood`: `"great"` | `"good"` | `"neutral"` | `"low"` | `"very_low"`
    - `stress_level`: `1` to `5`
    - `sleep_quality`: `1` (Poor) | `2` (Okay) | `3` (Good)
    - `nutrition`, `physical_activity`, `academic_pressure`, `social_interaction`: `1` to `5`
  - Response (`201 Created`):
    ```json
    {
      "id": 42,
      "date": "2026-09-08",
      "mood": "neutral",
      "stress_level": 4,
      "sleep_quality": 2,
      "nutrition": 3,
      "physical_activity": 2,
      "academic_pressure": 4,
      "social_interaction": 3,
      "private_note": "Exam tomorrow morning.",
      "support_signal": true,
      "support_reason": "High stress reported for 3 consecutive days",
      "date_range": {
        "from": "2026-09-06",
        "to": "2026-09-08"
      }
    }
    ```
  - Error: If duplicate date submitted for same student ➔ `409 Conflict`:
    ```json
    {
      "detail": "A check-in for this date has already been submitted."
    }
    ```

- `GET /api/v1/checkins`
  - Headers: `Authorization: Bearer <student_token>`
  - Query Parameters:
    - `from`: Optional ISO date (`2026-09-01`)
    - `to`: Optional ISO date (`2026-09-08`)
  - Response (`200 OK`): Array of check-in objects ordered by date descending.

### 5. Staff Dashboard & Support Signals (Staff Role Only)

- `GET /api/v1/staff/support-signals`
  - Headers: `Authorization: Bearer <staff_token>`
  - Response (`200 OK`):
    ```json
    [
      {
        "id": 1,
        "student_id": "usr-atharva",
        "student_name": "Atharva Dev",
        "student_email": "student@codeforge.local",
        "date_from": "2026-09-06",
        "date_to": "2026-09-08",
        "signal_type": "high_stress_streak",
        "reason": "High stress (>= 4) for 3 consecutive days",
        "status": "active",
        "created_at": "2026-09-08T00:00:00Z"
      }
    ]
    ```
  - **PRIVACY SHIELD NOTE**: The private student notes are completely excluded from this response.

- `PUT /api/v1/staff/support-signals/{signal_id}/status`
  - Headers: `Authorization: Bearer <staff_token>`
  - Request: `{"status": "acknowledged"}` or `{"status": "resolved"}`
  - Response (`200 OK`): Updated signal object.
